# x402 compatibility

ProofRails supports a Flare-mainnet paid-resource sequence that combines USD₮0 settlement, protected-resource delivery, receipt creation, signed evidence packaging and bundle anchoring.

<img src="/assets/x402-mainnet-flow.svg" alt="ProofRails paid-resource integration on Flare mainnet" />

## ProofRails integration

Use the product configuration and unlock endpoints exposed by the ProofRails paid-resource application:

1. read the active chain, token, facilitator, recipient, amount and resource configuration;
2. sign a USD₮0 `TransferWithAuthorization` payload;
3. submit the authorization to the ProofRails X402Facilitator on Flare;
4. call the unlock endpoint with the settlement reference;
5. receive the protected resource and ProofRails receipt;
6. retrieve the signed bundle and Flare anchor.

Unlock requests are idempotent for a completed payment reference.

## Standard x402 V2 clients

The current HTTP challenge is a ProofRails-specific exchange. It uses `X-PAYMENT-REQUIRED` and a version `1.0` response body rather than the standard x402 V2 `PAYMENT-REQUIRED`, `PAYMENT-SIGNATURE` and `PAYMENT-RESPONSE` header exchange.

Official `@x402/fetch` and `@x402/evm` clients therefore cannot be used as drop-in clients for this endpoint. Integrate against the ProofRails configuration and unlock APIs until the protected endpoint exposes the standard V2 challenge format.

## Developer checks

Before submitting an authorization:

- match chain ID `14` and the configured USD₮0 contract;
- validate the facilitator, recipient, amount, resource and authorization deadline;
- set explicit value and gas bounds;
- use an idempotency key for receipt writes;
- verify resource-delivery hashes when the delivered files must be covered by the evidence bundle.
