# x402 payment-gated actions

ProofRails can require payment before executing selected API actions or unlocking a protected resource. It then records the payment and can create receipt evidence around it.

## Payment paths in current source

| Network | Asset | Mechanism |
|---|---|---|
| Flare mainnet | USD₮0 | EIP-3009 `TransferWithAuthorization` through X402Facilitator |
| Flare mainnet | FLR | Native transfer verification |
| Base mainnet | USDC | ERC-20 transfer-event verification |

Deployment operators can enable or disable paths independently.

## Premium actions

```http
POST /v1/x402/premium/verify-bundle
POST /v1/x402/premium/generate-statement
GET  /v1/x402/premium/iso-message/{receipt_id}/{type}
POST /v1/x402/premium/fx-lookup
POST /v1/x402/premium/bulk-verify
POST /v1/x402/premium/refund
```

Management and reporting:

```http
GET  /v1/x402/pricing
POST /v1/x402/pricing
GET  /v1/x402/payments
GET  /v1/x402/revenue
GET  /v1/x402/facilitator-config
POST /v1/x402/verify-payment
```

The hosted OpenAPI also exposes payment-specific receipt and compliance-check routes. Authorization varies by route and deployment.

## Flare USD₮0 configuration

See [Networks and contracts](/deployments) for verified mainnet addresses.

The EIP-3009 authorization must bind at least:

- token and chain ID;
- payer and recipient;
- exact raw amount;
- validity window;
- unique nonce;
- facilitator contract.

The facilitator verifies the authorization, rejects invalid or reused nonces, settles the transfer and records a payment ID.

## Compatibility warning

The proven x402test path uses custom product configuration and unlock calls. It is not a standard x402 V2 integration. Do not plug in an official v2 client and assume it will work. Read [x402 status and compatibility](/x402/status-and-compatibility) before integration.

## Local mock mode

```env
X402_MOCK_PAYMENTS=true
```

Mock mode skips onchain verification. Use it only for local development and automated tests. A mock success is not payment evidence.
