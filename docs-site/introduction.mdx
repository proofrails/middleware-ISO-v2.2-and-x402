## One API. A complete payment evidence trail.

Settlement confirms that value moved. ProofRails adds the financial context and portable evidence developers need after settlement: a normalized receipt, ISO 20022-style artifacts, a signed file inventory, and an independently checkable onchain commitment.

<img src="/assets/receipt-lifecycle.svg" alt="ProofRails pipeline from blockchain payment to finance-ready evidence" />

## What your integration receives

| Output | Developer interface | What it gives you |
|---|---|---|
| Receipt record | `GET /v1/iso/receipts/{receipt_id}` | Payment parties, chain, asset, amount, business reference, metadata and processing state. |
| Financial messages | `GET /v1/iso/messages/{receipt_id}` | ISO 20022-style payment, status, statement, return and investigation artifacts. |
| Signed evidence bundle | `/files/{receipt_id}/evidence.zip` | Receipt data, XML, canonical manifest, file hashes, Ed25519 signature and public key. |
| Onchain commitment | `GET /v1/anchors/{receipt_id}` | The bundle SHA-256 committed through EvidenceAnchor on Flare. |
| Verification result | `POST /v1/iso/verify` | Bundle integrity and comparison with the expected onchain commitment. |

## Built for payment and agent workflows

ProofRails works behind merchant checkouts, treasury and reconciliation systems, paid APIs, agent purchases, and x402-enabled resources. Your application supplies the payment reference and business context; ProofRails creates the evidence layer around it.
