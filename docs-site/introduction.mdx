# Verifiable receipts for onchain payments

ProofRails turns a blockchain payment reference into a receipt that people, applications and agents can inspect later. Each receipt can include normalized payment context, ISO 20022-style XML, a signed evidence bundle and an onchain commitment to the bundle hash.

ProofRails does not custody or transfer funds. It records evidence around a payment and makes that evidence easier to reconcile, exchange and verify.

<img src="/assets/receipt-lifecycle.svg" alt="ProofRails receipt lifecycle from payment reference to onchain verification" />

## Start with the outcome

A successful receipt flow gives you:

- a stable receipt ID and lifecycle status;
- the original payment reference and business context;
- finance-readable XML artifacts;
- a portable ZIP containing the receipt, manifest, file hashes and signature material;
- a SHA-256 bundle hash committed by the EvidenceAnchor contract;
- APIs and a public page for later verification.

## What you can build

| Use case | ProofRails role |
|---|---|
| Merchant payment receipts | Attach invoice, order or service context to an onchain payment. |
| Agent purchases | Record what an agent paid, which endpoint it called and the resulting receipt. |
| Reconciliation pipelines | Export payment activity as ISO 20022-style messages and statement artifacts. |
| Audit and dispute evidence | Preserve a signed, hash-inventoried evidence package and an onchain timestamped commitment. |
| Paid APIs and resources | Gate access with the ProofRails x402 implementation, then create and anchor a receipt. |
| Independent verification | Recompute bundle hashes, validate manifest signatures and compare them with an anchor event. |

## Current status

The hosted API is live and health-checked. Receipt creation, evidence bundles, ISO-style artifacts, verification, project and agent surfaces, Flare anchoring, and ProofRails' payment-gated endpoints are deployed.

A real Flare-mainnet product run has also completed: `0.001 USD₮0` settled through the ProofRails facilitator, unlocked two protected resources, created a receipt and produced a signed bundle whose hash matched a successful Flare-mainnet EvidenceAnchor transaction.

The current paid-resource flow is ProofRails-specific. It is **not yet interoperable with the standard x402 V2 client exchange**. The official v2 client could not parse the current custom payment challenge, and no payment was authorized in that conformance test. See [x402 status](/x402/status-and-compatibility).

## Evidence, not overclaiming

ProofRails can demonstrate that a particular bundle hash was created, signed and committed onchain. That does not by itself prove that an invoice is valid, that supplied metadata is true, that a party passed KYC, or that a payment has legal settlement finality.

Use “ISO 20022-style artifacts” unless a specific schema, market practice and certification claim has been separately validated for your deployment.
