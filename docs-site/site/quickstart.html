Quickstart

This guide runs the current source locally with mock payment checks, creates a receipt and follows it to evidence generation. No blockchain transaction is required for the local flow.

Prerequisites

  • Git
  • Docker with Compose
  • curl

1. Start the stack

git clone https://github.com/proofrails/middleware-ISO-v2.2-and-x402.git
cd middleware-ISO-v2.2-and-x402
git checkout agentic
cp .env.example .env

Set local-only values in .env:

API_KEYS=dev-admin-CHANGE_ME
X402_MOCK_PAYMENTS=true
RATE_LIMIT_ENABLED=false
AUTO_CREATE_DB=true

docker compose up --build

Check readiness:

curl --fail http://localhost:8000/v1/health

OpenAPI is available at http://localhost:8000/docs.

2. Create a receipt

curl --fail-with-body -X POST http://localhost:8000/v1/iso/record-tip \
  -H 'X-API-Key: dev-admin-CHANGE_ME' \
  -H 'Idempotency-Key: quickstart-invoice-001' \
  -H 'Content-Type: application/json' \
  -d '{
    "reference": "invoice-001",
    "tip_tx_hash": "0x1111111111111111111111111111111111111111111111111111111111111111",
    "chain": "flare",
    "amount": "100.00",
    "currency": "FLR",
    "sender_wallet": "0x1111111111111111111111111111111111111111",
    "receiver_wallet": "0x2222222222222222222222222222222222222222",
    "metadata": {"invoice_id": "invoice-001", "environment": "local"},
    "tags": ["quickstart", "invoice"]
  }'

Save the returned receipt_id. In the current source, operation_id is the same UUID.

3. Poll processing

curl --fail http://localhost:8000/v1/operations/<receipt_id> \
  -H 'X-API-Key: dev-admin-CHANGE_ME'

Expected lifecycle:

pending → processing → awaiting_anchor → anchored
                                ↘ failed

Use 2–5 second polling intervals in development. Prefer webhooks in production.

4. Fetch the outputs

curl --fail http://localhost:8000/v1/iso/receipts/<receipt_id> \
  -H 'X-API-Key: dev-admin-CHANGE_ME'

curl --fail http://localhost:8000/v1/iso/messages/<receipt_id> \
  -H 'X-API-Key: dev-admin-CHANGE_ME'

curl --fail --output evidence.zip \
  http://localhost:8000/files/<receipt_id>/evidence.zip

5. Verify the bundle

curl --fail-with-body -X POST http://localhost:8000/v1/iso/verify \
  -H 'X-API-Key: dev-admin-CHANGE_ME' \
  -H 'Content-Type: application/json' \
  -d '{"bundle_url":"http://localhost:8000/files/<receipt_id>/evidence.zip"}'

A local mock run can validate bundle integrity but cannot prove a real mainnet anchor. For a public read-only example, follow the mainnet proof walkthrough.
