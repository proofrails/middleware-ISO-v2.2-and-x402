Flare integration

ProofRails uses Flare for tamper-evident receipt commitments and the verified USD₮0 paid-resource flow. The current source also includes FTSO v2 data helpers and FDC attestation preparation.

Evidence anchoring

Hosted mainnet contract:

0x235f83a74fc9D759D648eC533d2c06712F3Ca5EA

An anchor writes the current bundle hash to EvidenceAnchor. Applications should store the resulting transaction hash with the receipt and independently confirm the emitted hash.

For hosted ProofRails receipts, anchoring is a completion requirement. Keep a receipt in awaiting_anchor or failed until the current bundle hash is committed and independently matched. If signed bundle bytes change, anchor the new hash before presenting the updated receipt as complete.

Self-hosted configuration:

FLARE_RPC_URL=https://flare-api.flare.network/ext/C/rpc
ANCHOR_CONTRACT_ADDR=0x...
ANCHOR_PRIVATE_KEY=<runtime-secret-reference>

Do not place a literal private key in an image, document, repository or browser build.

Platform and tenant modes

  • Platform anchoring: the ProofRails worker signs and submits the anchor.
  • Tenant anchoring: the tenant submits the transaction and calls POST /v1/iso/confirm-anchor with the receipt ID, chain and transaction hash.

Use tenant mode when your organization must control the signing key or gas policy.

Retry

Current source:

POST /v1/iso/receipts/{receipt_id}/retry-anchor

Retry only after fixing the underlying RPC, funding, key, contract or worker problem. An anchor proves the integrity and timing of the committed hash, not the truth of offchain data.

FTSO helpers

Current source routes:

GET /v1/flare/feeds
GET /v1/flare/feeds/{symbol}

These return FTSO v2 feed information and live values. Availability in the hosted API should be confirmed at runtime.

FDC preparation

Current source:

POST /v1/flare/fdc/prepare-attestation

This prepares an FDC attestation request body for a transaction. Preparing a request is not the same as obtaining and verifying a finalized FDC proof. Document the full attestation lifecycle separately when that production flow is deployed and tested.
