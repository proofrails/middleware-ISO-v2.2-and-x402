Receipts API

Create

POST /v1/iso/record-tip

See Create a receipt for the complete payload.

List

GET /v1/receipts
Query Description
status Filter by lifecycle status.
chain Filter by chain name.
reference Filter by external reference.
since, until ISO-formatted date boundaries.
tags Comma-separated tags; source requires all listed tags.
scope mine by default; all requires admin access.
cursor Stable cursor for agents and concurrent insert workloads.
page, page_size Legacy offset pagination.

Use next_cursor for subsequent calls. Cursor pagination is safer than page numbers while receipts are being inserted.

Poll status

Current source:

GET /v1/operations/{operation_id}
GET /v1/iso/receipts/{receipt_id}/status

These lightweight endpoints return status, bundle hash, anchor transaction and timestamps without the full receipt payload. They were not present in the hosted OpenAPI snapshot checked on 24 July 2026; hosted clients should discover support at runtime.

For hosted ProofRails receipts, anchored is the completed state. The receipt remains incomplete while it is pending, processing, awaiting_anchor or failed.

Retry failed anchoring

Current source:

POST /v1/iso/receipts/{receipt_id}/retry-anchor

The receipt must be failed and already have a bundle hash. A successful retry request resets it to awaiting_anchor and queues the anchor job.
