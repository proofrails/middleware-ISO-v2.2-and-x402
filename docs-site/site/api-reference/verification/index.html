Verification API

Verify bundle evidence

POST /v1/iso/verify

{
  "bundle_url": "https://app.proofrails.com/files/<receipt_id>/evidence.zip",
  "bundle_hash": "0x<optional-expected-sha256>"
}

At least one input must be present. Supplying both lets the service download the bundle and compare it with your expected hash.

Response fields:

Field Meaning
matches_onchain Whether the service found a matching anchor under its configured chain and contract.
bundle_hash SHA-256 computed or supplied for the bundle.
flare_txid Matching anchor transaction when found.
anchored_at Anchor time when available.
checksums Optional file-level verification details.
errors Download, ZIP, signature, manifest or chain lookup failures.

Verify CID

POST /v1/iso/verify-cid

Use this for evidence stored on IPFS or Arweave. The SDK supports ipfs, arweave and auto selectors.

List receipt anchors

GET /v1/anchors/{receipt_id}

Verification discipline

A hosted matches_onchain: true result is useful, but independent verification should also check chain ID, EvidenceAnchor address, transaction status, decoded event hash and the locally recomputed ZIP SHA-256.
