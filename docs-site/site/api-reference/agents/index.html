Agents API

ProofRails represents an autonomous service as a project-scoped agent record. Agents can be configured, tested, linked to payment activity and used to create anchor records.

Hosted CRUD and operations

POST   /v1/agents
GET    /v1/agents
GET    /v1/agents/{agent_id}
PUT    /v1/agents/{agent_id}
DELETE /v1/agents/{agent_id}
GET    /v1/agents/{agent_id}/stats
POST   /v1/agents/{agent_id}/test
POST   /v1/agents/{agent_id}/test-ai
PUT    /v1/agents/{agent_id}/ai-config
POST   /v1/agents/{agent_id}/download-template

The hosted OpenAPI checked on 24 July includes these routes. Use it for exact schemas.

Current-source anchoring

GET  /v1/agents/{agent_id}/anchoring-config
PUT  /v1/agents/{agent_id}/anchoring-config
POST /v1/agents/{agent_id}/anchor-data
POST /v1/agents/{agent_id}/anchor
GET  /v1/agents/{agent_id}/anchors
GET  /v1/agents/{agent_id}/activity-unified

anchor-data canonicalizes a JSON object with sorted keys and compact separators, computes SHA-256, stores only the hash in the anchor record and optionally queues an onchain submission.

{
  "data": {
    "task_id": "task-42",
    "result_hash": "0x...",
    "payment_id": "0x..."
  },
  "description": "Agent task completion",
  "chain": "flare",
  "submit_onchain": false
}

Set submit_onchain to false when you only need a deterministic canonical hash or when signing is handled by another service.

Unified activity

GET /v1/agents/{agent_id}/activity-unified merges x402 payment records and anchor events into a time-ordered feed with payment and anchor summary counts.

Security

Do not send a private key through this API until the deployment's secret-storage implementation has been reviewed and uses proper encryption or an external signer. Prefer a vault, HSM or tenant-side signing flow.
