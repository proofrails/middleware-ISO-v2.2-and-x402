x402 compatibility

This integration uses real USD₮0 on Flare mainnet. It is not a testnet faucet flow or a payment simulation.

Current compatibility

The hosted ProofRails paid FX endpoint completed the standard x402 V2 exchange with unmodified @x402/fetch and @x402/evm version 2.19.0 on 29 July 2026.

The live-verified sequence covered:

  • HTTP 402 and PAYMENT-REQUIRED;
  • official-client PAYMENT-SIGNATURE generation;
  • server-submitted settlement through the ProofRails X402Facilitator;
  • an HTTP 200 protected FX response;
  • standard PAYMENT-RESPONSE with an actual receipt ID and verifier URL;
  • resource hash capture in the receipt and signed bundle;
  • ISO 20022-style artifacts;
  • Ed25519 manifest verification;
  • a Flare EvidenceAnchor event matching the current bundle hash.

Integration boundary

ProofRails operates an integrated x402 facilitator for its own payment-gated APIs; on Flare, USDT0 settlement uses the ProofRails X402Facilitator contract.

ProofRails does not expose a generic public HTTP /verify and /settle facilitator service for unrelated merchant APIs. Integrate against the payment-gated routes that appear in the hosted OpenAPI or deploy the source for your own environment.

Replay behavior

The verified payment nonce was rejected after settlement with HTTP 409 nonce_already_used. Sequential replay and two concurrent duplicate requests produced no second payment transaction.

The source verifier also checks chain, token, recipient, minimum amount, transaction status and confirmation policy. New payment paths should repeat the complete production evidence and adversarial test matrix before they are described as validated.

Developer checks

Before a client signs:

  • confirm Flare chain ID 14;
  • match the live USD₮0 contract, facilitator and recipient;
  • inspect the exact raw amount and authorization deadline;
  • apply explicit fee and value bounds;
  • keep one nonce per authorization;
  • preserve PAYMENT-RESPONSE and the returned receipt reference;
  • verify the delivered resource hash against the receipt and signed bundle.
