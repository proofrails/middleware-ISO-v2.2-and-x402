Onchain anchoring

Anchoring commits the current evidence-bundle hash onchain. The anchor contains a timestamped commitment to the evidence state rather than the whole receipt.

Completion invariant

A hosted ProofRails receipt is complete only when the hash of its current evidence bundle has been committed through EvidenceAnchor and the receipt exposes the matching anchor transaction.

Before that point, the receipt must show its real lifecycle state, such as pending, processing, awaiting_anchor or failed. An application must not present an unanchored receipt as complete.

If any signed bundle bytes change after an anchor, ProofRails must create a new bundle hash and anchor that new hash before treating the updated receipt as complete.

What verification means

A verified anchor supports this statement:

The supplied bundle bytes hash to the same value committed by the identified onchain anchor transaction.

It does not independently establish the truth of offchain data, legal sufficiency, accounting treatment or ISO 20022 compliance.

Failure handling

RPC, gas, funding, key, contract or worker failures can delay anchoring. Keep the receipt in awaiting_anchor or failed, expose the error operationally and retry only after fixing the underlying cause.

POST /v1/iso/receipts/{receipt_id}/retry-anchor

The public verifier should display anchored only after the current bundle hash and the onchain event match.
